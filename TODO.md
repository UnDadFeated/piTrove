# TODO - piTrove Bug Tracking

This file tracks identified bugs, errors, and architectural weaknesses in the piTrove codebase. All previously resolved items have been cleared to maintain focus on the active backlog.

## Active Backlog (Audit Cycle 3 — June 2026)

| ID | Component | Severity | Description & Proposed Fix | Breakage Risk | Status |
|---|---|---|---|---|---|
| 1 | preload.cpp:61-74 | Medium | **Worker threads detached on shutdown** — `PreloadQueue::shutdown()` detaches worker threads instead of joining them. If a worker is mid-malloc or mid-I/O when the process exits, heap corruption or file descriptor leaks can occur. **Fix**: Set a shutdown timeout (e.g. 2s), attempt join first, only detach as last resort with a log warning. | LOW — detach is fallback, join is preferred | OPEN |
| 2 | preload.cpp:306-313 | Medium | **Nested mutex deadlock risk** — `worker_thread` holds `work_mutex` and then tries to acquire `queue_mutex` via `scoped_lock` inside `work_cv.wait()` predicate. The predicate lambda acquires `queue_mutex` while already under `work_mutex` lock. `scoped_lock` avoids ordering issues, but the nested acquisition in the wait predicate is fragile and can stall if another thread holds `queue_mutex` and waits on `work_mutex`. **Fix**: Refactor so the predicate only checks `work_queue` (already under `work_mutex`), and check `loaded_items` capacity outside the predicate, or use a single atomic counter for capacity. | LOW — `scoped_lock` prevents deadlock but stall risk remains | OPEN |
| 3 | mqtt.cpp:91-102 | Low | **Shell injection via MQTT publish command** — `escape_shell_arg` wraps values in single quotes but doesn't strip null bytes or control characters. A malicious MQTT broker/topic configuration could embed `'\x00'` or other control chars to break out. **Fix**: Add null-byte and newline filtering in `escape_shell_arg`. | NONE — defense-in-depth improvement | OPEN |
| 4 | mqtt.cpp:230 | Low | **Empty sensor_topic subscribed** — If `mqtt_motionsensor_topic` is empty, `mosquitto_sub` receives an empty `-t ""` argument, which causes it to subscribe to all topics on the broker (wildcard behavior). **Fix**: Only add the sensor topic `-t` argument when `sensor_topic` is non-empty. | NONE — fixes silent over-subscription | OPEN |
| 5 | scanner.cpp:324 | Low | **Wrong mutex type for config read** — `scan_directory()` uses `std::lock_guard` (exclusive lock) on `g_config_mtx` which is a `shared_mutex`. Should use `std::shared_lock` for read-only access to avoid blocking other readers. **Fix**: Change `std::lock_guard lk(g_config_mtx)` to `std::shared_lock lk(g_config_mtx)`. | NONE — strictly correct, reduces contention | OPEN |
| 6 | scanner.cpp:263 | Low | **Zero threads when hardware_concurrency equals 1** — `num_threads = std::min(hw_cores - 1, (int)subdirs.size())` yields 0 when `hw_cores == 1`, which the `if (num_threads < 1) num_threads = 1` below catches. But `chunk = subdirs.size() / num_threads` is computed *before* the clamp, yielding division by zero on single-core machines when subdirs is empty. **Fix**: Move the `num_threads < 1` guard before the chunk calculation, or combine with `std::max`. | NONE — order-of-operations fix | OPEN |
| 7 | tui.cpp:387 | Medium | **Exclusive lock on shared_mutex for read-only TUI access** — `sv()` lambda correctly uses exclusive lock for writes, but `gv()` lambda accesses `g_cfg` without any lock at all, racing with config writes from other threads. **Fix**: Add `std::shared_lock lk(g_config_mtx)` to the `gv()` lambda body. | LOW — adds correct locking to already-racy reads | OPEN |
| 8 | cache.cpp:74 | Low | **Exclusive lock for read-only config access** — `CacheManager::open()` uses `std::lock_guard lk(g_config_mtx)` to read `g_cfg.cache_mmap_size`. Should use `std::shared_lock` since `g_config_mtx` is a `shared_mutex`. **Fix**: Change to `std::shared_lock`. | NONE — reduces lock contention | OPEN |
| 9 | cache.cpp:211-212 | Medium | **Writing to const MediaItem reference** — `CacheManager::upsert()` takes `const MediaItem& mi` but writes to `mi.is_camera` and `mi.creation_time` on lines 212-213. This is undefined behavior per the C++ standard (modifying a const reference). The code compiles because `is_camera` and `creation_time` are `mutable` in the struct. **Fix**: Verify `mutable` is intentional; if not, change `upsert()` parameter to non-const or cache the values locally. | LOW — behavior is correct if mutable, UB if not | OPEN |
| 10 | renderer.cpp:265 | Low | **Exclusive lock for read-only config in calculate_fit_rect** — Uses `std::lock_guard lock(g_config_mtx)` but only reads config values. Should use `std::shared_lock`. **Fix**: Change to `std::shared_lock`. | NONE — reduces lock contention | OPEN |
| 11 | renderer.cpp:342 | Low | **Exclusive lock for read-only config in draw_background** — Same issue as #10. `std::lock_guard lk(g_config_mtx)` should be `std::shared_lock`. **Fix**: Change to `std::shared_lock`. | NONE | OPEN |
| 12 | renderer.cpp:983 | Low | **Accessing g_cfg.edge_glow_shadow without lock** — `draw_bias_lighting()` reads `g_cfg.edge_glow_shadow` directly without holding `g_config_mtx`. This is a data race if config is changed concurrently (e.g. via TUI or HTTP). **Fix**: Read `edge_glow_shadow` from the already-captured config snapshot passed as parameter, or add a shared lock. | NONE — adds thread safety | OPEN |
| 13 | util.cpp:687 | Low | **Exclusive lock for read-only config in perform_nas_online_check** — Uses `std::lock_guard<std::shared_mutex>` (exclusive) to read `g_cfg.media_dir`. Should use `std::shared_lock`. **Fix**: Change to `std::shared_lock`. | NONE | OPEN |
